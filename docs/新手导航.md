# 新手导航：这个项目现在长什么样

> 看不懂的时候先翻这一页，不要翻代码。这页只回答三个问题：这是什么、现在有什么、下一步会看到什么。

## 一、一句话说清这个项目

这是一个"带权限的 AI 问答平台"的后端。用户登录后按角色决定能做什么，可以向 AI 提问，AI 会引用知识库里的文档回答，最后还能让多个 AI 角色分工合作答一道题。

做完它要分四步：先有登录，再分权限，然后接对话和知识库，最后做多智能体。**每一步验收通过，才做下一步。**

## 一之二、你的需求，分三层看

最外面一层是做东西。做一个带权限的 AI 问答平台后端，四步走完：登录、按角色分权限、对话加知识库、多智能体协作。用的人是你自己，加上你后面会创建的其他测试账号；前端在 5176 端口；最终要部署到远程服务器。

中间一层是学东西。写的过程中要真正学会 Python、MySQL、Redis、LangChain 四样。标准不是"代码跑起来了"，而是"你能自己改得动"。所以每一段代码都配自改任务和自测题，改不动就不算学会。

最里面一层是协作方式。AI 当教练不当代写，一次只给一个小功能，先讲后写，写完停下等你说继续，你说看不懂就必须拆开重讲。这一层是我最容易违反的，也是你最在意的。

## 一之三、项目现在的要求，分四层，不要混着看

第一层是硬约束，写在 `AGENTS.md`，任何阶段都成立。技术栈锁死 FastAPI + SQLAlchemy 2.0 同步写法 + MySQL 8，禁止改用异步驱动。四个阶段顺序不许跳，不许自行添加需求外的功能。分层上，api 只收参数、校验、调 service，不写 SQL 不 commit；业务逻辑和事务都在 service 层；禁止 api 直接 import models。代码上，函数不超过 30 行，嵌套不超过 2 层，单文件不超过 400 行，每个函数上方三行注释，变量名用完整单词，禁止吞异常、禁止顺手重构、禁止自行装依赖。

第二层是协作流程，写在 `learning-contract.md`。动手前先讲背景和最多 3 个新概念，然后停下等你确认。单次给出的代码不超过 60 行。写完说清数据怎么流、指出最该看懂哪几行，然后停下。你提问时先答问题，不许边答边写。阶段结束更新术语表、出 3 道自测题。

第三层是随阶段生效的专项规则。数据库规则在 `rules\db.md`，阶段一、二读：每张表必备 id、created_at、updated_at、is_deleted 四列，软删除，不建物理外键，状态字段用常量类不用裸数字，列表查询必须分页且有上限，禁止在循环里查库。LLM 规则在 `rules\llm.md`，阶段三才开始读，现在不用管。

第四层是你已经拍板的业务决定，写在 `progress.md` 第四节。token 用 JWT，有效期 30 分钟，不做刷新，也不做黑名单（留到阶段三用 Redis 补）。响应统一成 code、message、data。登录失败连续 5 次锁 10 分钟，先用内存实现。不做公开注册，改成管理员创建用户。跨域只放 5176 两个地址。

## 二、现在做到哪了

到现在为止，一行业务代码都还没写。前面几轮做的事全部是地基，打个比方：房子还没砌第一块砖，但现在地基平了、电路通了、施工规范也立好了。

具体完成四件事。第一件，选定工具 uv，把"要装哪些库、每个库什么版本"固定下来，以后换台电脑也能装出一模一样的环境。第二件，把文件夹按职责划好，谁能放什么、不能放什么写进了规则。第三件，把 AI 要遵守的规矩写成文件，一共六份文档，各管一件事。第四件，做了配置层，让全项目只有一个地方读密码和地址，缺了就直接启动失败。

真正的登录代码从第 8 步开始。现在在第 3 步和第 4 步之间，所以你觉得"没看到东西"是正常的——确实还没有能跑给人看的功能。

## 三、项目里每个东西是干什么的

先看根目录。`AGENTS.md` 是施工规范，AI 每次开工前要读它，里面只有必须遵守的硬规矩，80 行，写多了会稀释重点。`pyproject.toml` 是材料清单，写明要用哪些库、版本范围多大。`uv.lock` 是按清单算出的精确采购单，连每个包的哈希都记着，这份必须提交，服务器只认它。`.python-version` 只有一行，声明用 3.12。

`.env.example` 是配置模板，里面只有字段名和占位值，进 git。`.env` 是同样一份东西但填了真实密码，你自己建，永远不进 git。`.venv` 是装好的环境，41 个包都在里面，它不进 git，因为随时能从 `uv.lock` 重建。

`app\` 是代码目录。`app\core\config.py` 是目前唯一有内容的代码文件，干一件事：把 `.env` 读成一个能校验的对象。其余目录都是空的包，位置先占好，等人入住。

`docs\` 是指南。`progress.md` 是进度表，每次开工先看它。`architecture.md` 是地图，哪个文件该在哪一目了然。`commands.md` 是命令手册，跑命令前从这儿取，不靠记忆。`learning-contract.md` 是学习流程，规定怎么讲、什么时候停。另外两份是术语表和沟通格式约定。

`tests\` 放测试，`scripts\` 放一次性脚本，现在还空着。根目录那两个 `uv_*_log.txt` 是排查网络问题时留下的日志，可以直接删。

## 四、以后一次登录请求怎么走

你在浏览器或前端点登录，请求先到 `app\api\v1\auth.py`，这一层只负责收参数。参数格式交给 `app\schemas` 里的模型检查，不合格当场拒绝。然后转到 `app\services`，这里做真正的业务：按 `app\models` 定义的 `users` 表结构，通过 `app\db` 给的数据库连接去查人、比对密码、签发 token。结果再转成统一结构返回。

这七个格子现在都空着，但位置已经定死。以后你写代码只是往格子里填东西，不会到处乱放。

## 五、现在出现过的词，一句话解释

uv：一个管依赖和虚拟环境的工具，比 pip 快，还能顺便锁版本。
虚拟环境：给这个项目单独一间屋子装库，不和其他项目抢用。
依赖：项目要用到的第三方库，比如 FastAPI、SQLAlchemy。
锁定文件：精确记录"到底装了哪一版"的文件，保证换机器装出一样的结果。
环境变量：操作系统里的键值对，用来放密码、地址这类不该写进代码的东西。
配置对象：把散落的环境变量集中成一个带类型、会校验的东西。
校验：值不对就当场报错，而不是等运行到一半才炸。
ORM：用 Python 对象操作数据库表，不用手写 SQL 拼字符串。
迁移：表结构改了以后，把改动记录成一份可重复执行的脚本。
路由：一个 URL 对应一个处理函数。
依赖注入：函数需要的工具由框架递进来，不用自己 new。
JWT：登录后发的一串带签名的凭证，服务端不用存也能验真假。

## 六、现在能验证什么

第一条，`uv run python -c "import app, app.api.v1"` 不报错，说明包结构对。第二条，配好 `.env` 后打印配置对象能出九个值。第三条，把密码或密钥删掉再启动，应该在启动时就报 `Field required`。这三条都过了，地基就是真的牢，不是看起来牢。

## 七、下一步会看到什么

第 4 步写错误处理和日志，这一步看不见效果，但后面每一次报错都靠它定位。第 5 步连数据库，第一次能亲眼看到"真的连上了"，会有报错风险，连不上就停。第 6 步做健康检查接口，这是第一个能用浏览器访问的东西。第 7 步建 `users` 表并生成迁移。第 8 步写第一个真正的接口。

如果你觉得"一直没看到东西"，可以调顺序，把第 6 步提到第 5 步前面，先让你能用浏览器打开一个页面，再回去连数据库。要不要调，你定。
