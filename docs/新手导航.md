# 新手导航：这个项目现在长什么样

> 看不懂的时候先翻这一页，不要翻代码。这页只回答三个问题：这是什么、现在有什么、下一步会看到什么。

## 一、一句话说清这个项目

这是一个"带权限的 AI 问答平台"的后端。用户登录后按角色决定能做什么，可以向 AI 提问，AI 会引用知识库里的文档回答，最后还能让多个 AI 角色分工合作答一道题。

做完它要分四步：先有登录，再分权限，然后接对话和知识库，最后做多智能体。**每一步验收通过，才做下一步。**

## 一之二、你的需求，分三层看

最外面一层是做东西。做一个带权限的 AI 问答平台后端，四步走完：登录、按角色分权限、对话加知识库、多智能体协作。用的人是你自己，加上你后面会创建的其他测试账号；本机后端在 8081、前端在 5178；最终要部署到远程服务器。

中间一层是学东西。写的过程中要真正学会 Python、MySQL、Redis、LangChain 四样。标准不是"代码跑起来了"，而是"你能自己改得动"。所以每一段代码都配自改任务和自测题，改不动就不算学会。

最里面一层是协作方式。AI 当教练不当代写，一次只给一个小功能，先讲后写，写完停下等你说继续，你说看不懂就必须拆开重讲。这一层是我最容易违反的，也是你最在意的。

## 一之三、项目现在的要求，分四层，不要混着看

第一层是硬约束，写在 `AGENTS.md`，任何阶段都成立。技术栈锁死 FastAPI + SQLAlchemy 2.0 同步写法 + MySQL 8，禁止改用异步驱动。四个阶段顺序不许跳，不许自行添加需求外的功能。分层上，api 只收参数、校验、调 service，不写 SQL 不 commit；业务逻辑和事务都在 service 层；禁止 api 直接 import models。代码上，函数不超过 30 行，嵌套不超过 2 层，单文件不超过 400 行，每个函数上方三行注释，变量名用完整单词，禁止吞异常、禁止顺手重构、禁止自行装依赖。

第二层是协作流程，写在 `learning-contract.md`。动手前先讲背景和最多 3 个新概念，然后停下等你确认。单次给出的代码不超过 60 行。写完说清数据怎么流、指出最该看懂哪几行，然后停下。你提问时先答问题，不许边答边写。阶段结束更新术语表、出 3 道自测题、补这一页。

第三层是随阶段生效的专项规则。数据库规则在 `rules\db.md`，阶段一、二读：每张表必备 id、created_at、updated_at、is_deleted 四列，软删除，不建物理外键，状态字段用常量类不用裸数字，列表查询必须分页且有上限，禁止在循环里查库。LLM 规则在 `rules\llm.md`，阶段三才开始读，现在不用管。

第四层是你已经拍板的业务决定，见 [进度与已定方案](progress.md)。JWT 默认有效期 30 分钟，服务端登出已接入，刷新尚未接入。登录失败锁定改用 Redis 计数（Redis 不可用时回退进程内存）。新账号通过管理员接口创建。

## 二、现在做到哪了

阶段一的登录、当前用户查询、登录失败锁定和管理员建用户都已有实现。前端已有登录页和首页。新环境的首个管理员初始化限制见 [脚本说明](scripts.md)。

登录成功会拿到 JWT。带上它请求 `/auth/me`，可以查询用户名、显示名、账号状态和管理员标记。凭证失效返回 401。已停用的账号在身份校验通过后返回 403。同一输入用户名连续输错 5 次会锁定 10 分钟。

管理员通过 `POST /users` 创建普通账号，接口按权限码 `users:create` 放行，不再看 `is_admin`。RBAC 已有四张表和种子脚本；给用户追加和撤销角色、停用与启用账号都在阶段二收尾完成。前端退出会先调 `POST /auth/logout`，后端把该账号的令牌版本加一，已签发的旧 token 立刻失效，不是等到过期。

## 三、项目里每个东西是干什么的

根目录那几份文件没变。`AGENTS.md` 是施工规范，`pyproject.toml` 是材料清单，`uv.lock` 是精确采购单，`.env.example` 是配置模板，`.env` 由你自己填真实值且不进 git，`.venv` 随时能从锁文件重建。

`app\core\` 放与业务无关的工具。`config.py` 读环境变量，`errors.py` 定义业务异常并统一翻译成响应，`logging.py` 配日志，`security.py` 做密码哈希和 token 签发验签。

`app\db\` 只有两个文件。`session.py` 建全项目唯一的连接池和会话工厂，`base.py` 定所有表的基类和约束命名规则。

`app/models/user.py` 定义 `users` 表，共 9 列（比第一阶段多的一列是 `token_version`，用来让旧令牌失效）。`app/models/rbac.py` 定义角色、权限和两张关联表。表和列的中文注释通过 `alembic/versions/` 中的迁移写入数据库。

`app/schemas/` 定义请求和响应字段。`app/services/auth.py` 负责登录、身份校验和退出登录，`login_guard.py` 记录失败次数，`password.py` 管密码哈希与改密，`user.py` 负责建用户和切换账号状态，`rbac.py` 管角色、权限和授权边界。

`app/api/v1/auth.py` 提供登录、当前用户、权限清单、改密和退出接口。`app/api/v1/users.py` 提供用户列表、建用户、角色追加撤销和状态切换接口。`app/api/deps.py` 取 token、加载当前用户，并按权限码提供各种守卫（不再判断管理员身份）。`app/main.py` 挂载路由和全局异常处理。

`tests/` 现有 204 条用例，覆盖密码哈希、JWT、统一错误响应、登录失败锁定、RBAC 授权边界和令牌失效。`scripts/create_admin.py` 用于初始化首个账号，`scripts/seed_rbac.py` 用于初始化角色和权限。用法见 [脚本清单](scripts.md)。

`docs\` 里有进度表、架构地图、命令手册、学习流程、术语表、脚本清单、这一页导航，各自职责见 `AGENTS.md` 第七节。

## 四、一次登录请求怎么走

从前端说起。登录页点提交，`api/auth.ts` 发 `POST /api/auth/login`，Vite 代理把 `/api` 去掉，落到后端 `/auth/login`。

后端先用 `LoginRequest` 校验请求，字段不合格返回 422。`get_db` 提供数据库会话。登录服务先查锁定状态，再查用户、验密码和确认账号状态。成功后签发 JWT。

结果包成 `{code, message, data}` 返回。前端把 `access_token` 存进 Pinia 和 localStorage，跳 `/home`。

首页再发 `GET /auth/me`。这次请求头里有 `Authorization: Bearer token`，`api/deps.py` 把它取出来，service 验签解出 user_id，按 id 查库确认人还在、状态正常，返回用户信息。任何一步不对，异常都在 `core/errors.py` 被接住，转成 401 或 403。

## 五、现在出现过的词，一句话解释

uv：一个管依赖和虚拟环境的工具，比 pip 快，还能顺便锁版本。
虚拟环境：给这个项目单独一间屋子装库，不和其他项目抢用。
依赖：项目要用到的第三方库，比如 FastAPI、SQLAlchemy。
锁定文件：精确记录"到底装了哪一版"的文件，保证换机器装出一样的结果。
环境变量：操作系统里的键值对，用来放密码、地址这类不该写进代码的东西。
配置对象：把散落的环境变量集中成一个带类型、会校验的东西。
校验：值不对就当场报错，而不是等运行到一半才炸。
ORM：用 Python 对象操作数据库表，不用手写 SQL 拼字符串。
迁移：表结构改了以后，把改动记录成一份可重复执行的脚本。
路由：一个 URL 对应一个处理函数。
依赖注入：函数需要的工具由框架递进来，不用自己 new。
JWT：登录后发的一串带签名的凭证，服务端不用存也能验真假。
Bearer：请求头里带 token 的固定写法，服务端只认这个格式。
会话：一次请求里和数据库打交道的草稿纸，用时才借连接。
连接池：养着若干条连接的池子，借了要还，池子满了就排队。
统一响应：所有接口都套 code/message/data 同一个外壳。
守卫：换页前先检查有没有登录票，没有就打回去。

## 六、现在能验证什么

用 `uv run pytest -q` 跑全量用例，当前 204 条全绿；临时文件固定在项目根的 `.pytest-tmp`（已 git 忽略，别手动删正在跑的目录）。联调时可检查 `GET /health`、登录和 `GET /auth/me`。已登录的普通用户调用 `POST /users` 应返回 `403 / 2001`。启动和测试命令见 [命令手册](commands.md)。
