# 知识库检索质量

## 怎么读表

- **命中率**是至少返回一个切片的问题数除以总问题数。返回切片表示当前检索规则找到了候选，相关性仍由人工判断。
- **期望 top1 / top3 命中率**只统计填写了期望标题的问题。把返回切片的所属文档标题与期望标题精确比较。`—` 表示没有填期望标题。当 `top_k` 小于 3 时，top3 只在实际返回的条目中检查。
- **top1 分数**来自 MySQL 全文检索，保留三位有效数字。小语料下真命中也可能只有 `1e-2` 到 `1e-8`。分数受库内语料分布影响，绝对分只在同一组语料内参考。
- **top1 区间**为原文字符区间，左闭右开。标题来自文档列表，切片总数来自各文档切片分页的 `total`。耗时 p50 是本轮搜索 HTTP 请求耗时的中位数。
- **候选与丢弃**分别对应检索响应的 `candidates` 和 `dropped`。丢弃数等于候选数减去命中数，包含被阈值筛除的切片和因 `top_k` 截断而未返回的切片。旧记录保留当时的表格格式。
- **混合检索下 top1 分数是两路合计**：关键词、向量各自除以本路最高分后相加，两路第一名是同一块时接近 2。它和 MySQL 全文分数不是同一口径，只在同一轮内比较。

探针词的取法分两条路（2026-11-25 起）：短问句仍按原规则剥「什么是 / 是什么」等前后缀，剥完不超过 6 字就直接当探针；剥完仍是一大段长句时，改从本次候选正文里挑片段——在问句的 2~5 字片段中，取「覆盖候选数 × 片段长度」最高、且不是疑问用语、也不是覆盖全部候选的那一个。

- 选「覆盖 × 长度」而不是「长度优先」：长度优先会挑到只命中一块的罕见片段，实测把「上传纯文本知识库文档如何同步切片？」的 top1 从 architecture 顶成 scripts（32.4 → 26.3 反超），属于改恶。
- 长句不再让机制空转：五题探针由改前的 0 命中变为 3 / 3 / 2 / 3 / 1 条命中；但五题的命中数、top1 分数与 top1 文档全部与 16:47 基线一致，说明这轮改动只是让机制真正参与，没有改变现有排序结果。
- 局限仍在：覆盖×长度偏好主题词，像「切片编号」这种只在少数块出现的具体词选不上；真正需要「把含具体词的块提前」的场景，还要靠更细的词表或词频统计。

## 什么时候评估向量库

满足以下任意一项才进入「评估向量库」环节。三项都未触发时，继续使用现有关键词检索。

1. 命中率 **低于 60%**。
2. 期望文档 top3 命中率 **低于 70%**。
3. 人工判读的前三条切片中，明显不相关的条数 **超过三分之一**。用相同的 `top_k` 查询原接口，阅读返回的前三条正文和所属文档，再手工记录判读条数与理由。

期望标题为空的题目不参与期望命中率。保持每轮都有期望题，并尽量使用贴近真实场景的问法。脚本只统计接口返回与标题匹配，人工意见留在报告里另行填写。

## 怎么跑两轮

1. 准备一层 UTF-8 `.txt` 或 `.md` 文件。使用默认五题时，至少把仓库的 `docs/architecture.md`、`docs/chat.md`、`docs/验收/阶段二.md` 和 `docs/scripts.md` 放进语料目录，保留原文件名。先离线预览，再实际导入。记录汇总中的目标库编号。
2. 固定语料目录、库编号、问题文件和 `top_k`，在当前阈值下跑第一轮。然后在启动后端的终端设置 `SEARCH_MIN_SCORE_RATIO` 或 `SEARCH_MIN_SCORE_ABSOLUTE`，重启服务，再跑评测。每轮用 `--threshold-note` 标出实际生效的阈值，脚本会写进本轮标题。此参数只标记报告，后端设置决定实际阈值。

```powershell
$corpusDir = Read-Host '语料目录'
$password = Read-Host -MaskInput '本地评测账号密码'
uv run --no-sync python scripts/corpus_import.py --dry-run --dir $corpusDir --username admin --password $password
uv run --no-sync python scripts/corpus_import.py --dir $corpusDir --username admin --password $password
$baseId = Read-Host '导入输出的知识库编号'
uv run --no-sync python scripts/search_eval.py --base-id $baseId --username admin --password $password --threshold-note 'ratio=0.5 / abs=0'
```

每轮在下方追加一个带时间戳的表。把两轮放在左右窗口并排看，按同一问题对比命中数、期望标题、原文区间和耗时，然后补人工标注。请求失败的一轮会退出并报告出错的问题。
