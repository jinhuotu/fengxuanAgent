# 边写边学协作流程（docs/learning-contract.md）

> 我要的不是一个写完的代码库，我要在写的过程中学会。以下是**硬流程**，不是建议。
> 每轮开工前读一遍，照着做。**输出格式一律遵守 `docs/沟通格式约定.md`：先结论、一段一个意思、少列表、多短句。**

## 一、动手前：先讲，再写

1. 用 3-5 句话讲清这一步的背景：它在整个系统里处在什么位置、为什么现在做它。
2. 列出这一步用到的新概念，**最多 3 条**，每条一句话解释 + 一个生活化比喻。
3. 说明这一步要创建或修改哪些文件，每个文件一句话职责。
4. **停下来**，等我确认后再开始写。

## 二、写代码时

- 单次给出的代码不超过 60 行。超了就是一次做了太多，拆成两步，中间停下来讲一遍再继续。
- 每个新概念第一次出现，加一行 `# 新手注意：……`，用比喻解释。
- 关键分支、循环、依赖注入的位置加注释说明"在做什么"，不要逐行翻译代码。
- 无论是新文件还是改动，遵守 AGENTS.md 第三节（函数 ≤30 行、三行注释、完整变量名）。

## 三、写完必须停下来

- 用 3 句话说明这次的数据怎么流动。
- 明确指出"你最该看懂的是第 a 行到第 b 行"，并说明为什么是这两行。
- 主动问一句"这里要不要我讲细一点"。
- **等我回"继续"再动下一步**，不要连续往下做。

## 四、我提问时

1. 先回答问题，**不要边回答边继续写代码**。
2. 概念类问题用比喻讲，不贴官方文档原文，不堆术语。
3. 涉及 Python 特有写法（推导式、with、装饰器、生成器、async），补一句"在 Java 里对应什么，没有对应就直说没有"。
4. 回答完问一句"继续刚才的进度吗"，我确认再往下。

## 五、每阶段结束

1. 更新 `docs/术语表.md`，一行一个：`JWT —— 把"我是谁"写在纸上并盖章，服务端能验章 —— 用在登录接口`
2. 出 3 道自测题考我（数据流向 / 某处为什么这么写 / 改动某个条件会怎样），我答完再判对错，并指出我漏掉的点。
3. 更新 `docs/新手导航.md`（阶段一结束时创建）：新增了哪些文件、一次请求的完整链路。
4. 更新 `docs/progress.md` 的阶段状态。

## 六、每次交付必须给（五条）

1. 文件清单：每个文件一句话作用。
2. 数据流转：5 行以内白话讲清"请求从哪进、经过哪几步、结果到哪去"。
3. 改动定位：我要改提示词 / 接口地址 / 参数，分别该动哪个文件第几行。
4. 完整命令：启动、测试怎么跑（从 docs/commands.md 取）。
5. 追加三行到 `docs/progress.md`：日期 / 决定了什么 / 为什么。

## 七、验收清单（逐条回报，每条给证据）

- [ ] `python -m compileall app` 通过
- [ ] 服务能启动、无报错（贴关键日志）
- [ ] 相关测试通过（贴结果）
- [ ] 没有新增依赖（或已获我同意）
- [ ] 改动只涉及事先声明过的文件
- [ ] 每个新函数上方都有三行注释
- [ ] 涉及数据库改动时，迁移文件已生成并说明影响哪张表

## 八、阶段学习地图（开工前先说清"我在学什么"）

- **阶段一 登录**：路由与依赖注入、Pydantic 校验、密码哈希、JWT、HTTP 状态码。
- **阶段二 权限**：RBAC 是什么、用依赖注入做鉴权、中间件与依赖的区别、权限表设计。
- **阶段三 对话 + 知识库**：模型调用封装、流式输出（SSE）、文本切分、检索与上下文拼装、引用来源怎么返回。
- **阶段四 多智能体**：角色定义、编排流程、状态与消息传递、失败重试。

## 九、不许跳步的三件事

1. 不许一次做完一个阶段。一个阶段拆成 5-8 个小功能，一个一个验收。
2. 不许为了"看起来专业"引入我没听过、也没同意过的库（详见 AGENTS.md 第四节）。
3. 不许在我还没看懂上一段代码的时候继续往下写。我会直接说"停"。
